### Finding 2. Which row a multi-parent node is revealed at (fixed)

- **What.** Find commands and selections from the other panes reveal a node at the row reached through `Parents.FirstOrDefault()`, stopping when that first parent is the root. `Parents` is in the order the links were made, and the port lost that order in three places.
  1. A node made at the root and then linked into a group has the root first, so upstream reveals the root row. The port always preferred a group.
  2. A move inside one parent (drag to reorder, Reverse) removes the link and makes it again, so that parent becomes the last one. The port left the order alone.
  3. On load a group links its children only after all of them are read, so a child that a deeper group listed later also holds gets the deeper group first. The port linked each child as it was read.
- **C#.** `Vixen.Common/Controls/ElementTree.cs:243-254`; `Vixen.Core/Sys/GroupNode.cs:10-18, :43-48, :78-84`; `Vixen.Core/Sys/Managers/NodeManager.cs:37-53, :60-65`; `Vixen.Core/IO/Xml/Serializer/XmlElementNodeSerializer.cs:94-95`.
- **Port.** `crates/vixen-session/src/setup/tree.rs` (`TreeNode::parents_before_root`, `drop_parent`, `add_child_to_parent`, `move_node`, `first_parent_path`); `crates/vixen-io/src/system.rs` `read_node`.
- **Tests.** `setup::tree::tests::first_parent_path_follows_the_order_the_links_were_made`, `system::tests::parents_are_in_the_order_the_groups_finish_reading`.
- **Left over.** Upstream keeps the link order in memory until it quits. The port keeps it for one Display Setup window: after OK the shared tree only knows "at the root or not", so a reopened window treats the root as the last parent, as a restart of upstream would.
- **Status.** Fixed.

### Finding 3. OK kept an element name the file had when it differed from its node's (fixed)

`ElementNode`'s constructor sets `element.Name = name` for every node read (`Vixen.Core/Sys/ElementNode.cs:29-33`: "Ensure the element name matches the ElementNode name") and the `Name` setter keeps it so (`:94-104`), so every `<Channel>` a save writes carries its node's name. The owner's show has no such channel (1,133 leaves checked), so its byte-identical round trip is unchanged. Not changed: `vixen_io::system::load_system` still hands other areas the file's channel name until a Display Setup OK; see the report's other areas.

### Finding 4. The controller type list was in byte order, not alphabetical (fixed)
