# Vixen 2 import-color ownership verification

The Set Import Color edit now stays with the rows selected when the chooser opens. The fixed compiled callbacks pass **18 checks**; the same suite against the previous callback found **eight expected failures**. This verifies callback ownership and private map persistence. It does not establish physical system-picker or mapping-drag behavior.

The original `Vixen2xSequenceImporterChannelMapper.cs:411–428` opens a modal `ColorDialog` at red and applies the selected color only after `DialogResult.OK`. The Mac previously read the current selection on every nonmodal panel callback, so changing selection redirected the edit. It also left its target active after map cancellation and bypassed any existing `ColorPanelSession` owner. The fix in `app/Sources/VixenScheduler/Vixen2ImporterWindow.swift` captures row indices, uses the existing shared session, and opts into committing unchanged red. The Mac retains its documented commit-on-close/takeover convention for the nonmodal system panel; this is not a claim that its close control is Windows ColorDialog Cancel.

Each model tracks whether it still owns the color edit. The session clears that flag on end, before committing. Clear, drop, OK and Cancel finish only that model's edit, so an old map cannot finish a newer editor's session. OK receives the committed draft before saving. Map Cancel still discards the draft and leaves the saved map unchanged. The Cancel button now calls this cleanup method.
