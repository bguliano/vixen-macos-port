# Prop and shared native color ownership

The Prop state color editor and the shared color session now transfer ownership through AppKit's exclusive `NSColorWell` protocol. The previous implementation could commit a new editor's blue into an earlier Vixen 2 map, or change a Prop state item when a different editor chose cyan. Both failures were reproduced with active native wells and persisted files, rather than inferred from similar code.

`ColorPanelSession` owns a private, unmounted native well. Activating it exclusively deactivates an existing native or SwiftUI well before assigning the new session's color. Another well taking over deactivates the session's well and commits its pending color. `finish()` clears callback state before deactivation and invokes completion afterward, preserving exactly-once commits and a new session started by `onEnd` or `onFinish`.

Prop's actual table double-action now uses the shared session and captures the state item's UUID. Its existing noncontinuous delivery remains. A final color matching the already-applied live value skips the full model refresh: otherwise that refresh removed a second native well while it was taking ownership. The Rust edit result supplies this no-op check. A distinct magenta edit advances the revision once, persists, and does not add another undo step on finish. The upstream custom Prop editor uses a modal chooser and applies only its accepted result; the port retains its documented nonmodal commit-on-close/takeover convention.

The consolidated record is `target/prop-color-ownership-final/result.json`. Final source hashes are `3845c6797ef95ef4337a85209a5e7291eafe8144bcf779b70093d239bd5f2015` for `ColorControls.swift` and `8ade12790a0c84ce527f93cbcbe26b72d43a73248f2379f2f23787896f179ddb` for `PropStates.swift`.

The five final suites contain 83 assertions; the 64 sheet steps are the inputs to 12 of those assertions, not additional independent assertions. Compiled executables and the recorded compiler inputs are frozen. Actual canonical Cocoa and Rust preference file hashes are unchanged across the final regression batch, and all owned harness processes exited. The older shared/sheet runners freeze their recorded inputs but do not independently inventory every transitive compiler input or measure foreground ownership; those limits remain explicit in the aggregate record.

The Prop fixture mounts actual compiled `PropStatePanel`, `StateColorWell`, `Vixen2MapModel` and Rust editors. It suppresses public panel presentation methods only inside its private process; controlled `NSTableView.clickedRow` and `clickedColumn` getters feed the real table double-action. The color setter dispatches to the actual native callback. No callback implementation is copied, but this is not a physical double-click, picker or Quick Picks gesture test.

The separate production SwiftUI `ArgbColorPicker` fixture proves the generic native-well route: five baseline failures become 13 passes using its real `PlatformColorWell` and binding. See `docs/review/swiftui-color-takeover.md`. That fixed fixture used the earlier `fdf096c8…` shared-session source. Subsequent changes preserved normal ownership logic and added the Prop no-op guard, comment relocation and test-only presentation protection. Its 13 checks are separate from the final 83; other SwiftUI picker screens are not individually claimed as tested.

The UITest-only presentation protection sets panel alpha to zero before activation. A defer hides it, moves it offscreen again and restores its previous alpha. AppKit really orders the transparent panel during activation; this is not a “never ordered” claim. The normal app path does not modify alpha and still presents the panel normally. The earlier unguarded `prop-color-vixen2-regression-01` retained 18 passing native behavior checks but failed a Python outside-screen assertion before final preferences/save verification. Its old metadata omitted actual frames/screen inventory, so exact placement cannot be inferred. It is retained as a failed acceptance attempt.

Other historical qualifications remain: fixed01's original blue-to-blue double-action check did not prove a changed-color callback; fixed02/fixed04 replace it with magenta and an exact revision increment. The baseline03 fixture's older scope string omitted its controlled table getters; the actual source and this note identify them. After the final Vixen 2 observer run, only its stale source-header wording was corrected; the exact compiled snapshot remains pinned and the executable body is unchanged.
